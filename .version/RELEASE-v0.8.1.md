# Release v0.8.1

> 核心变化：**先探索代码库，再产出总结**。意图复述从「被允许只读探查」改为「必须先只读探查」，并新增「已核实的现状」输出段；dev 命令的提示词补上同一份只读探查规则，堵住「不读代码就给计划」的路径。

## 🚀 Features

### `/dev-pre-check`：复述前必须先只读探查代码库

意图复述此前只是「允许」只读探查，代理容易凭需求描述推测代码库现状，复述与实际代码脱节。本次把探查提为复述的前置要求，并让探索结果在输出里有可见落点：

- **新增共享探查规则 `READ_ONLY_EXPLORATION_RULES`** — 由 `extensions/pre-check.ts` 导出，供复述指令与 dev 命令共用同一份文案：
  - 用 `read` / `grep` / `glob` 等只读工具确认：入口文件、现有实现、相关测试、项目约定与配置
  - 不臆测文件路径、接口签名、依赖与既有行为
  - 相关概念在代码库中确实不存在时，明确写出「未发现」并交代检索范围
  - 探查到足以支撑产出为止，不做与任务无关的全库通读
- **新增「探索要求（先只读探查，再复述）」段** — 明确「复述前必须先看真实代码，不要凭需求描述推测代码库现状」
- **输出格式由四段改为五段** — 新增首段 `### 1. 已核实的现状（探索结果）`：要求每条事实带真实文件路径与符号名（如 `src/auth/login.ts:42` — 现有校验逻辑），未找到的内容须写「未发现 …」并说明检索范围；原四段顺延为 2-5
- **「不确定之处」收紧** — 能靠只读探查消除的先查完再写；剩下的须区分「已读代码确认」与「仅推测」
- **硬性约束补明副作用边界** — 「禁止运行任何有副作用的命令」细化为「（安装、构建、测试、git 写操作等）」，与只读探查的定位一致

### dev 命令：提示词新增「探索要求」段

四类 dev 命令此前只在各自的职责条目里零散提到「先读代码库」，力度不足以挡住不读代码就给出实施计划的行为：

- **复用同一份探查规则** — `dev-prompts.ts` 引入 `READ_ONLY_EXPLORATION_RULES`，在「已确认的任务意图」与「身份与职责」之间插入「探索要求（先只读探查，再动手）」段，并要求「实施计划里引用的文件与符号都必须是本轮真实读到的」
- **职责条目具体化** — 去掉与探查段重复的「先读代码库」前缀，改为可执行动作：
  - `/dev-feat`：给出逐步实施计划（要修改/新建的文件、迁移、对现有代码的假设），经确认后再写代码
  - `/dev-fix`：先用只读探查定位根因（相关代码、日志、调用链），不用消除报错的方式掩盖症状
  - `/dev-refactor`：先指出要消除的具体结构性问题（带真实文件与位置），再动手
- **组装结构** — 提示词现为：任务（原始描述）→ 已确认的任务意图 → 探索要求 → 身份与职责 → 验收标准

### 测试与文档同步

- 结构断言更新：dev 命令的 `pre-check` 复用断言改为「依赖 `./pre-check` + 调用 `confirmIntent(`」，新增 5 条断言覆盖共享探查规则、两个「探索要求」段与复述首段格式（共 86 条，全部通过）
- README 同步：pre-check 流程新增「先探索再复述」步骤、输出格式改为五段、dev 提示词结构示例补「探索要求」段
